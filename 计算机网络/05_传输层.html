05 传输层 ​

本章是计算机网络最核心的章节，TCP 三次握手/四次挥手、可靠传输机制、流量控制与拥塞控制是历年大题必考内容。

一、传输层概述 ​

传输层提供**端到端（进程到进程）**的逻辑通信。

协议特点应用
UDP无连接、不可靠、面向报文DNS、DHCP、RTP
TCP面向连接、可靠、面向字节流HTTP、FTP、SMTP

端口号 ​

  • 端口号范围：0~65535
  • 熟知端口号（0~1023）：FTP=21, SSH=22, SMTP=25, DNS=53, HTTP=80, HTTPS=443, POP3=110
  • 套接字 Socket = (IP 地址, 端口号)

复用与分用 ​

  • 复用：多个应用进程可以使用同一传输层协议传送数据
  • 分用：传输层根据端口号将数据分发到不同的应用进程

二、UDP 协议 ​

2.1 UDP 特点 ​

  1. 无连接：发送前不需要建立连接
  2. 不可靠：尽最大努力交付，不保证可靠传输
  3. 面向报文：对应用层交下来的报文既不合并也不拆分（保留报文边界）
  4. 首部开销小（8 字节）
  5. 支持一对一、一对多、多对一、多对多通信

2.2 UDP 首部格式 ​

源端口目的端口长度校验和
2B2B2B2B

校验和：计算时需要加上 12 字节的伪首部（源 IP + 目的 IP + 0 + 协议号 + UDP 长度）

三、TCP 协议 ​

3.1 TCP 特点 ​

  1. 面向连接：使用前需建立连接，使用后释放连接
  2. 全双工通信
  3. 可靠传输
  4. 面向字节流：把数据看作无结构的字节流
  5. 点对点通信（一对一）
  6. 首部最小 20 字节，最大 60 字节

3.2 TCP 报文段格式 ​

关键字段：

字段大小说明
源/目的端口各 2B
序号 seq4B本报文段数据第一个字节的序号
确认号 ack4B期望收到的下一个字节的序号
数据偏移4位首部长度，以 4B 为单位
保留6位保留
URG1位紧急指针有效，优先传送
ACK1位确认号有效（连接建立后 ACK 恒=1）
PSH1位尽快交付给应用层
RST1位连接出错，必须释放后重建
SYN1位连接建立（SYN=1 时不能携带数据，但消耗一个序号）
FIN1位释放连接（FIN=1 时可以携带数据）
窗口2B接收窗口大小（用于流量控制）
校验和2B首部+数据+伪首部
紧急指针2BURG=1 时有效

seq 和 ack 的计算规则

  • seq：本报文段第一个数据字节的编号
  • ack：期望对方发来的下一个字节的编号 = 收到的 seq + 数据长度
  • SYN 和 FIN 各消耗一个序号（即使不携带数据）

【例】 A 发送 seq=100 的报文段（携带 200B 数据）→ B 回复 ack=300

  │                            │

为什么要三次握手？

防止已失效的连接请求报文段突然又到达服务器。如果只有两次握手，服务器可能会白白建立连接浪费资源。

四次挥手（释放连接） ​

客户端                          服务器
  │── FIN=1, seq=u ───────────▶│  第一次挥手（FIN_WAIT_1）
  │◀── ACK=1, ack=u+1 ────────│  第二次挥手（CLOSE_WAIT）
  │  （FIN_WAIT_2）             │
  │◀── FIN=1, seq=w, ack=u+1 ─│  第三次挥手（LAST_ACK）
  │── ACK=1, ack=w+1 ─────────▶│  第四次挥手
  │  （TIME_WAIT, 等待 2MSL）    │  （CLOSED）
  │  （CLOSED）                 │

为什么 TIME_WAIT 要等待 2MSL？

  1. 保证最后一个 ACK 能到达服务器（超时可重传）
  2. 使本连接所有报文段在网络中消失，防止影响新连接

3.4 TCP 可靠传输 ​

以字节为单位的滑动窗口机制：

  • 发送窗口：由接收方的接收窗口 rwnd 和拥塞窗口 cwnd 共同决定
  • 确认机制：累积确认 + 超时重传
  • 序号机制：对每个字节编号
  • 校验和：检测数据是否出错

超时重传时间 RTO 的计算：

RTO=RTTs+4×RTTd

3.5 TCP 流量控制 ​

  • 接收方通过窗口字段告知发送方自己的接收能力
  • 发送窗口 ≤ rwnd
  • rwnd = 0 时，发送方启动持续计时器，定期发送零窗口探测报文

3.6 TCP 拥塞控制 ​

四个阶段：

慢开始 (Slow Start) ​

  • cwnd 从 1 MSS 开始，每收到一个 ACK，cwnd 翻倍（指数增长）
  • 达到慢开始门限 ssthresh 后转为拥塞避免

拥塞避免 (Congestion Avoidance) ​

  • cwnd 线性增长（每个 RTT 加 1）
  • 超时：ssthresh = cwnd/2，cwnd = 1，重新慢开始

快重传 (Fast Retransmit) ​

  • 收到 3 个重复 ACK 时立即重传丢失的报文段（不等超时）

快恢复 (Fast Recovery) ​

  • ssthresh = cwnd/2，cwnd = ssthresh（而非从 1 开始）
  • 直接进入拥塞避免阶段

拥塞控制核心

  • 超时 → cwnd=1，ssthresh=cwnd/2（慢开始）
  • 3 个重复 ACK → ssthresh=cwnd/2，cwnd=ssthresh（快恢复）
  • 发送窗口 = min(rwnd, cwnd)
