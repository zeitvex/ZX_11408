06 应用层 ​

本章涵盖常用应用层协议。以选择题为主，需要记忆各协议使用的端口号和传输层协议。

一、DNS（域名系统） ​

1.1 功能与特点 ​

  • 功能：域名 → IP 地址的映射（域名解析）
  • 使用 UDP，端口号 53（大量数据时也可用 TCP）
  • 采用分布式层次数据库

1.2 域名结构 ​

主机名.三级域名.二级域名.顶级域名
例：www.example.com
1
2

顶级域名分类：国家顶级域名（.cn/.us）、通用顶级域名（.com/.org/.edu）

1.3 DNS 服务器层次 ​

  • 根域名服务器：全球 13 组
  • 顶级域名服务器：管理各顶级域名
  • 权威域名服务器：管理区域内的域名映射
  • 本地域名服务器：ISP 提供，不属于层次结构

1.4 域名解析过程 ​

  1. 主机先查本地 DNS 缓存
  2. 向本地域名服务器发送查询
  3. 本地域名服务器执行：
    • 递归查询：代替主机向上级服务器查询（一般主机→本地DNS用递归）
    • 迭代查询：返回下一个应查询的服务器地址（一般DNS服务器之间用迭代）

二、FTP（文件传输协议） ​

  • 使用 TCP
  • 两个连接：控制连接（端口 21，始终保持）+ 数据连接（端口 20）
  • 两种模式：主动模式（PORT）/ 被动模式（PASV）
  • 客户端和服务器都需要建立两个进程

三、电子邮件 ​

3.1 邮件系统组成 ​

用户代理 → MTA（发送方邮件服务器）→ MTA（接收方邮件服务器）→ 用户代理

3.2 相关协议 ​

协议功能传输层端口
SMTP发送邮件TCP25
POP3接收邮件（下载后删除/保留）TCP110
IMAP接收邮件（在服务器上管理）TCP143

SMTP 只能传送 ASCII 文本

非 ASCII 数据（附件、图片等）需要通过 MIME 扩展进行编码。

四、HTTP（超文本传输协议） ​

4.1 基本特点 ​

  • 使用 TCP，端口号 80（HTTPS 为 443）
  • 无状态协议（使用 Cookie 维持状态）
  • HTTP/1.0：非持久连接（每个请求一个 TCP 连接）
  • HTTP/1.1：持久连接（默认，一个 TCP 连接可传送多个请求）
    • 非流水线方式：收到响应后才发下一个请求
    • 流水线方式：不等响应就连续发送请求

4.3 HTTP 状态码 ​

状态码类别常见值
1xx信息100 Continue

4.4 HTTPS ​

  • HTTP + SSL/TLS 加密
  • 端口号 443
  • 对称加密传输数据 + 非对称加密交换密钥 + CA 证书验证身份

五、DHCP（动态主机配置协议） ​

  • 使用 UDP，客户端 68，服务器 67
  • 四步过程：Discover → Offer → Request → ACK
  • 全部使用广播方式
  • 分配的 IP 地址有租约期限

六、输入 URL 后的完整过程（综合题） ​

跨章节综合考点

此过程贯穿应用层→传输层→网络层→数据链路层→物理层，是理解网络协作的核心。

  1. DNS 解析：浏览器缓存 → 本地 hosts → 本地 DNS 服务器 → 递归/迭代查询 → 获得 IP
  2. TCP 三次握手：与目标 IP 的 80/443 端口建立连接
  3. 发送 HTTP 请求：构造请求报文（GET /index.html HTTP/1.1）
  4. 网络层封装：加上 IP 首部（源/目的 IP），查路由表确定下一跳
  5. ARP 解析：若下一跳 MAC 未知，ARP 广播获取
  6. 数据链路层封装：加上 MAC 帧首部尾部
  7. 物理层传输：编码为比特流发送
  8. 逐跳转发：每个路由器解封到网络层 → 查路由表 → 重新封装 → 转发
  9. 服务器处理：解封到应用层 → 处理请求 → 构造 HTTP 响应
  10. 返回响应：按相反过程逐层封装返回
  11. 浏览器渲染：解析 HTML/CSS/JS → 显示页面
