03 内存管理 ​

本章是操作系统的第二大核心章节，涵盖内存管理基础、连续与非连续分配方式、虚拟内存技术。地址变换计算和页面置换算法是历年高频考点。

一、内存管理基础 ​

1.1 程序装入和链接 ​

将用户源程序变为可执行程序需要三个步骤：编译 → 链接 → 装入

链接方式：

方式特点
静态链接运行前将所有目标模块和库函数链接成完整的可执行程序
装入时动态链接装入内存时边装入边链接
运行时动态链接执行中需要目标模块时才链接，便于修改更新和共享

装入方式：

方式特点适用场景
绝对装入编译时产生绝对地址仅适用于单道程序
可重定位装入（静态重定位）装入时一次性完成地址转换多道程序，装入后不能移动
动态运行时装入（动态重定位）执行时才进行地址转换，需重定位寄存器现代操作系统使用

1.2 逻辑地址与物理地址 ​

  • 逻辑地址：编译后从 0 开始编址的相对地址，用户程序只需知道逻辑地址
  • 物理地址：主存储器的实际地址
  • 不同进程可以有相同的逻辑地址，映射到不同的物理位置

1.3 内存保护 ​

两种方法：

  1. 上下限寄存器：每次访存时检查地址是否在上下限之间
  2. 重定位寄存器 + 界地址寄存器：逻辑地址 < 界地址寄存器 → 加上重定位寄存器值 → 物理地址

1.4 进程的内存映像 ​

进程内存映像（高频选择题考点）

进程从外存调入内存运行后的布局结构，理解此图可串联 OS 与计组的多个知识点。

关键要点：

  • 栈从高地址向低地址增长，堆从低地址向高地址增长
  • 不同进程的内核区映射到相同物理页框（页面共享实现系统调用）
  • 每个进程的虚拟地址空间连续，但对应的物理页框离散分布

1.5 TLB + 页表 + Cache 三级寻址全流程 ​

大题核心考点（与计组存储系统联动）

此流程贯穿 OS 虚拟内存和计组 Cache 两个章节。

CPU 给出逻辑地址（虚拟地址）
    ↓ 拆分为 [虚拟页号 | 页内偏移]
查 TLB（快表，在 CPU 内部）
    ├─ 命中且有效 → 取出物理页框号 → 拼接物理地址 → 查 Cache
    └─ 未命中 → 查页表（慢表，在内存中）
                  ├─ 有效位=1 → 取页框号，更新 TLB → 拼接物理地址 → 查 Cache
                  └─ 有效位=0 → 缺页中断 → 调页 → 修改页表和TLB → 重新执行指令
查 Cache（用物理地址）
    ├─ 命中 → 取出数据
    └─ 未命中 → 访问主存 → 数据送入 Cache 和 CPU

访存次数分析：

场景访存次数
TLB 命中1 次（取数据）
TLB 未命中 + Cache 命中1 次（查页表） + 0 次（Cache 命中不访主存）
TLB 未命中 + Cache 未命中1 次（查页表） + 1 次（取数据） = 2 次
缺页缺页处理后重新执行，按上述规则重新计算

TLB 命中则不可能缺页

若数据在 TLB 中找到且有效位为 1，说明该页已在内存中，不可能发生缺页中断。

二、连续分配管理方式 ​

2.1 单一连续分配 ​

  • 内存分为系统区和用户区，仅用于单用户单任务
  • 无外部碎片，有内部碎片
  • 无须内存保护

2.2 固定分区分配 ​

  • 将用户内存空间划分为若干固定大小的区域，每个分区装一道作业
  • 分区大小可以相等，也可以不等
  • 用分区说明表管理（始址、大小、状态）
  • 有内部碎片，程序太大可能放不进任何分区

2.3 动态分区分配 ​

  • 根据进程大小动态建立分区，分区大小正好适合进程
  • 有外部碎片（可通过紧凑技术解决，需要动态重定位寄存器支持）

分配算法：

算法空闲分区排列特点
首次适应地址递增最简单，通常最好最快
最佳适应容量递增产生最多外部碎片
最坏适应（最大适应）容量递减很快无大内存块可用
邻近适应（循环首次适应）从上次结束位置继续通常比首次适应差

分配算法性能排序

实验表明：首次适应 > 最佳适应 > 最大适应

三、非连续分配管理方式 ​

3.1 基本分页存储管理 ​

核心概念 ​

  • 页面 (Page)：进程中的块，大小为 2 的整数幂
  • 页框 (Page Frame)：内存中的块
  • 页表：实现页号 → 物理块号的映射，每个进程一张，存放在内存中

地址结构 ​

逻辑地址=[页号 P][页内偏移 W]
  • 页号 P = 逻辑地址 / 页面大小
  • 页内偏移 W = 逻辑地址 % 页面大小

基本地址变换 ​

  1. 计算页号 P 和页内偏移 W
  2. 若 P ≥ 页表长度 M → 越界中断
  3. 页表项地址 = 页表始址 F + P × 页表项长度
  4. 取出物理块号 b
  5. 物理地址 E = b × 页面大小 + W

分页管理的地址空间是**一维**的

只需给出一个整数即可确定物理地址。

具有快表 (TLB) 的地址变换 ​

  • 快表 TLB：高速缓存，存放若干页表项
  • 命中快表：一次访存（取数据）
  • 未命中快表：两次访存（查页表 + 取数据）
  • 快表命中率可达 90% 以上

两级页表 ​

  • 目的：解决页表过大需要连续空间的问题
  • 顶级页表只能有 1 个页面
  • 以 32 位地址、4KB 页面、4B 页表项为例：地址格式为 10 | 10 | 12

3.2 基本分段存储管理 ​

  • 按用户进程中的自然段划分，每段从 0 开始编址
  • 段号和段内偏移必须由用户显式提供（高级语言中由编译器完成）
  • 段表项 = 段号 + 段基址 + 段长

地址变换 ​

  1. 取出段号 S 和段内偏移 W
  2. 若 S ≥ 段表长度 → 越界中断
  3. 从段表取出段长 C，若 W ≥ C → 越界中断
  4. 物理地址 = 段基址 + W

分段管理的地址空间是**二维**的

需要提供段号和段内偏移两个信息。分段有利于信息共享和保护。

段的共享与保护 ​

  • 纯代码（可重入代码）和不可修改的数据可以共享
  • 可修改的代码和数据不能共享

3.3 段页式管理 ​

  • 先分段，再将每段分页
  • 逻辑地址 = 段号 + 页号 + 页内偏移
  • 每个进程一张段表，每个分段一张页表
  • 一次访问需要三次访存（段表 + 页表 + 数据）
  • 地址空间是二维的（需要段号和页内地址）

3.4 分页 vs 分段对比 ​

对比项分页分段
目的提高内存利用率满足用户需求
长度页面大小固定段长不固定
地址空间一维二维
碎片内部碎片外部碎片
信息共享不便便于共享
对用户透明用户可见

四、虚拟内存管理 ​

4.1 基本概念 ​

基于局部性原理：

  • 时间局部性：被访问的指令/数据不久后可能再次被访问
  • 空间局部性：被访问的存储单元附近的单元可能也将被访问

虚拟内存特征：多次性、对换性、虚拟性

虚拟内存实际容量≤内存容量+外存容量虚拟内存最大容量≤地址位数能容纳的最大容量

4.2 请求分页管理 ​

在基本分页基础上增加了请求调页和页面置换功能。

请求页表项增加的字段：

字段含义
状态位 P该页是否已调入内存
访问字段 A记录访问次数/时间，供置换算法参考
修改位 M调入内存后是否被修改过
外存地址该页在外存上的位置

缺页中断特点：

  • 在指令执行期间产生（内部中断）
  • 一条指令可能产生多次缺页中断
  • 中断后回到引发中断的指令重新执行

4.3 页面置换算法 ​

算法原理特点
OPT（最佳）淘汰未来最长时间不再访问的页面缺页率最低，无法实现，仅用于评价
FIFO淘汰最早进入内存的页面可能出现 Belady 异常
LRU淘汰最近最久未使用的页面性能好，需硬件支持，不会 Belady 异常
CLOCK (NRU)循环扫描，淘汰使用位为 0 的页面性能接近 LRU
改进型 CLOCK在 CLOCK 基础上增加修改位首选未访问页，次选未修改页

Belady 异常

仅 FIFO 算法可能出现分配更多物理块反而缺页率更高的现象。LRU 等堆栈类算法不会出现。

4.4 页面分配策略 ​

策略特点
固定分配 + 局部置换驻留集固定，只能从自己的物理块置换
可变分配 + 全局置换缺页时 OS 分配空闲块，最简单
可变分配 + 局部置换根据缺页率动态调整驻留集，最优但复杂

不存在 "固定分配 + 全局置换"

全局置换会增加物理块，与固定分配矛盾。

4.5 抖动与工作集 ​

  • 抖动（颠簸）：进程频繁换页，换页时间多于执行时间
  • 工作集：某段时间内进程要访问的页面集合
  • 防止抖动：驻留集大小 ≥ 工作集大小
