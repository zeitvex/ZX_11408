04 文件管理 ​

本章涵盖文件系统基础、目录结构、文件的物理结构与存储空间管理以及磁盘组织。以选择题为主，磁盘调度算法的计算也时有考查。

一、文件系统基础 ​

1.1 文件的概念 ​

文件是以计算机硬盘为载体的存储在计算机上的信息集合。在用户进行的输入/输出中，以文件为基本单位。

文件包含：一块存储空间、分类和索引信息、访问权限信息。

文件的结构（自底向上）：

  1. 数据项：最低级的数据组织形式（基本数据项 / 组合数据项）
  2. 记录：一组相关数据项的集合
  3. 文件：有结构文件（记录式）/ 无结构文件（流式）

1.2 文件的属性 ​

名称、标识符、类型、位置、大小、保护（访问控制）、时间与用户标识。

所有文件信息保存在目录结构中，目录结构保存在外存上。

1.3 文件的基本操作 ​

操作说明
创建为文件找到空间 + 在目录中创建条目
写/读搜索目录查找位置，维护位置指针
重定位修改文件当前位置指针
删除删除目录项 + 回收存储空间
截断属性不变，仅删除文件内容

文件操作的系统调用流程 ​

1. open() 系统调用

c
int fd = open("/path/to/file", O_RDWR);
1

执行过程：

  1. 根据路径名逐级查找目录，定位到文件的 FCB
  2. 检查用户的访问权限（读/写/执行）
  3. 将 FCB 复制到系统打开文件表
  4. 在进程打开文件表中创建表项，指向系统表
  5. 返回文件描述符（fd，即进程表的索引）

2. read() 系统调用

c
ssize_t n = read(fd, buffer, count);
1

执行过程：

  1. 根据 fd 在进程打开文件表中找到对应表项
  2. 通过指针找到系统打开文件表中的 FCB
  3. 根据 FCB 中的文件位置指针，确定要读取的磁盘块
  4. 将数据从磁盘读入内存缓冲区
  5. 更新文件位置指针
  6. 返回实际读取的字节数

3. write() 系统调用

c
ssize_t n = write(fd, buffer, count);
1

执行过程类似 read()，但方向相反：

  1. 根据 fd 定位到 FCB
  2. 根据文件位置指针确定写入位置
  3. 将缓冲区数据写入磁盘
  4. 更新文件位置指针和文件大小
  5. 返回实际写入的字节数

4. close() 系统调用

c
close(fd);
1

执行过程：

  1. 删除进程打开文件表中的对应表项
  2. 系统打开文件表中的打开计数器 count−1
  3. 若 count = 0，则：
    • 将修改过的 FCB 写回磁盘
    • 删除系统打开文件表中的表项
    • 释放相关资源

打开文件表结构：

  • 系统打开文件表：全系统一张，记录 FCB 等信息
    • 包含：FCB 副本、打开计数器、文件锁等
  • 进程打开文件表：每个进程一张，记录系统打开表的索引
    • 包含：文件描述符、系统表索引、读写指针、访问模式等

文件描述符的本质

文件描述符（fd）本质上是进程打开文件表的数组下标。标准输入/输出/错误的 fd 分别为 0/1/2。

二、文件的逻辑结构 ​

2.1 无结构文件（流式文件） ​

以字节为单位的有序信息集合，适合源程序文件、目标代码文件等。

2.2 有结构文件（记录式文件） ​

类型特点适用场景
顺序文件记录顺序排列，可顺序/链表存储批量操作效率最高
索引文件索引表 + 逻辑文件，支持随机访问变长记录的快速检索
索引顺序文件记录分组 + 组索引平均查找次数 N
散列文件通过散列函数直接定位存取速度高，但有冲突

三、目录结构 ​

3.1 文件控制块 (FCB) ​

FCB 是实现"按名存取"的数据结构，一个 FCB 就是一个文件目录项。

FCB 包含：基本信息（文件名、物理位置）、存取控制信息（权限）、使用信息（时间）。

3.2 索引结点 (i 结点) ​

将文件名和文件描述信息分开：目录项 = 文件名 + i 结点指针。

优点：目录项缩小，一个盘块可装更多目录项，减少磁盘访问次数。

3.3 目录结构类型 ​

类型特点缺点
单级目录一张目录表不允许重名，不便共享
两级目录主文件目录 + 用户文件目录解决重名，但不能分类
多级（树形）目录层次化结构，支持绝对/相对路径查找需逐级访问中间结点
无环图目录在树形基础上允许共享管理复杂，需共享计数器

四、文件共享 ​

文件共享使多个用户共享同一个文件，系统中只保留一份文件数据。

4.1 硬链接（基于索引结点） ​

原理：多个目录项指向同一个 i 结点

实现机制：

  • i 结点中设置链接计数器 count，记录有多少个目录项指向该 i 结点
  • 用户 A 创建文件时，count = 1
  • 用户 B 共享该文件时，在 B 的目录中增加一个目录项，指向同一个 i 结点，count = 2
  • 删除文件时：
    • 仅删除对应用户目录中的目录项
    • count−1
    • 当 count = 0 时，系统才真正删除文件数据和 i 结点

特点：

  • ✅ 速度快：直接通过 i 结点访问文件
  • ✅ 节省空间：只有一份文件数据
  • ✅ 同步更新：任何用户修改文件，其他用户都能看到
  • ❌ 不能跨文件系统：硬链接只能在同一文件系统内创建
  • ❌ 不能链接目录：防止出现循环

示例：

用户 A 目录：file1 → inode #123 (count=2)
用户 B 目录：file2 → inode #123 (count=2)

2

4.2 软链接（符号链接） ​

原理：创建一个 LINK 类型的特殊文件，内容是被共享文件的路径名

实现机制：

  • 只有文件拥有者的目录项指向 i 结点
  • 其他用户创建的是一个新文件（LINK 类型），存储目标文件的路径
  • 访问时，操作系统根据路径名查找目标文件

特点：

  • ✅ 支持跨文件系统：可以链接到不同分区甚至网络文件
  • ✅ 可以链接目录
  • ✅ 灵活性高
  • ❌ 访问速度慢：需要先读取链接文件，再根据路径查找目标文件
  • ❌ 目标文件删除后链接失效：会出现"悬空链接"

示例：

用户 A 目录：file1 → inode #123
用户 B 目录：link1 → inode #456（LINK 类型，内容="/home/A/file1"）
1
2

4.3 硬链接 vs 软链接对比 ​

对比项硬链接软链接
实现方式多个目录项指向同一 inode创建新文件存储路径名
inode 数量共享同一个 inode各有独立的 inode
删除源文件不影响访问（count>0）链接失效（悬空）
跨文件系统❌ 不支持✅ 支持
链接目录❌ 不支持✅ 支持
访问速度快（直接访问）慢（需解析路径）
磁盘空间不占额外空间占用少量空间存路径

软链接的悬空问题

当源文件被删除后，软链接变成"悬空链接"，访问时会报错。但如果在原路径重新创建同名文件，软链接又会生效。

五、文件保护 ​

方式特点
访问控制列表 (ACL)规定每个用户的访问权限（拥有者/组/其他）
口令简单但不安全（口令存在系统内部）
密码（加密）保密性强但编解码耗时

六、文件分配方式 ​

考纲摘要：文件的物理结构，即文件数据在磁盘上如何分布和组织。

方式原理优点缺点
连续分配占有一组连续的块顺序/直接访问，速度快外部碎片，文件不宜动态增长
隐式链接每个盘块含下一块指针无外部碎片只能顺序访问，指针占空间
显式链接 (FAT)文件分配表存在内存中随机访问较快FAT 占内存空间
索引分配每个文件有索引块支持直接访问索引块占额外空间

索引分配的扩展：

  • 链接方案：将多个索引块链接起来
  • 多层索引：索引块指向下级索引块
  • 混合索引：直接索引 + 单级索引 + 多级索引

七、文件存储空间管理 ​

方法特点
空闲表法连续分配方式，类似内存动态分配
空闲链表法空闲盘块链（逐块分配）/ 空闲盘区链（成批分配）
位示图法一个二进制位对应一个盘块，0=空闲/1=已分配
成组链接法UNIX 使用，克服了表太大的缺点

位示图计算公式（从 1 开始编号）：

  • 盘块号 → 行列：i=(b−1)÷n+1，j=(b−1)modn+1
  • 行列 → 盘块号：b=n(i−1)+j

编号起始

若题目从 0 开始编号，公式需要相应调整！

八、磁盘组织与管理 ​

8.1 磁盘结构 ​

  • 盘面 → 磁道 → 扇区（盘块）
  • 所有盘片相同位置的磁道组成柱面
  • 磁盘地址 = 柱面号·盘面号·扇区号
  • 扇区是磁盘可寻址的最小存储单位

8.2 磁盘操作时间 ​

Ta=Ts+12r+brN
  • Ts（寻道时间）= m×n+s，OS 只能优化此项
  • 12r（旋转延迟）：平均半周
  • brN（传输时间）：b 为字节数，N 为每磁道字节数

8.3 磁盘调度算法 ​

算法原理特点
FCFS按请求到达顺序公平但性能差
SSTF选择距当前磁道最近的性能好但可能饥饿
SCAN（电梯）单方向扫描到底再反向解决饥饿，对刚扫描过的区域不公平
C-SCAN单方向扫描，回返时不服务更公平
LOOKSCAN 改进，到最远请求即返回实际常用
C-LOOKC-SCAN 改进，到最远请求即返回实际常用

磁盘调度计算题

要知道磁头当前位置和移动方向，计算磁头总移动磁道数和平均寻道长度。
