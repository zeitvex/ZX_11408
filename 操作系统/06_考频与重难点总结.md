## 二、选择题高频考点速查

### 第一章：操作系统概述

| 考点 | 要点 |
|------|------|
| 并发 vs 并行 | 并发是一段时间内，并行是同一时刻 |
| 四大特征 | 并发和共享是最基本特征，互为存在条件 |
| 互斥共享 vs 同时共享 | 打印机=互斥共享，磁盘=同时共享 |
| 用户态→核心态 | 唯一途径：中断/异常 |
| 核心态→用户态 | 中断返回指令（特权指令） |
| 访管指令（trap） | **不是特权指令**，只能在用户态使用 |
| 系统调用 | 运行在**核心态** |

### 第二章：进程管理

| 考点 | 要点 |
|------|------|
| PCB | 进程存在的**唯一标志** |
| 进程 vs 程序 | 进程是动态的，程序是静态的 |
| 线程 vs 进程 | 线程是**调度**的基本单位，进程是**资源分配**的基本单位 |
| 调度层次 | 高级（作业）→ 中级（内存）→ 低级（进程，最基本） |
| SJF 特点 | 平均等待时间/周转时间**最少** |
| FCFS 特点 | 对长作业有利，对短作业不利 |
| 同步 vs 互斥 | 同步=协调次序（直接制约），互斥=不能同时用（间接制约） |
| 死锁 vs 饥饿 | 死锁是循环等待，饥饿是一直得不到资源 |
| 死锁四条件 | 互斥 + 不剥夺 + 请求并保持 + 循环等待 |
| 安全状态 | 不安全状态**不一定**死锁，死锁一定处于不安全状态 |

### 第三章：内存管理

| 考点 | 要点 |
|------|------|
| 内部碎片 vs 外部碎片 | 内部：分配给进程但未用完；外部：太小无法分配 |
| 固定分区 | 有内部碎片 |
| 动态分区 | 有外部碎片（紧凑技术解决） |
| 分页 | 一维地址空间，对用户透明 |
| 分段 | 二维地址空间，用户可见，便于共享 |
| TLB 命中 | 一次访存（取数据） |
| TLB 未命中 | 两次访存（查页表+取数据） |
| Belady 异常 | **仅 FIFO** 可能出现 |
| LRU | 堆栈类算法，不会 Belady 异常 |
| 虚拟内存 | 基于局部性原理，需离散分配方式支持 |

### 第四章：文件管理

| 考点 | 要点 |
|------|------|
| FCB | 一个 FCB = 一个目录项 |
| 硬链接 vs 软链接 | 硬链接指向 i 结点，软链接存储路径名 |
| 连续分配 | 有外部碎片，支持直接访问 |
| 链接分配 | 无外部碎片，隐式只能顺序访问 |
| FAT | 显式链接，在**内存**中，启动时读入 |
| 索引分配 | 支持直接访问，索引块占额外空间 |
| 位示图 | 注意编号从 0 还是从 1 开始 |

### 第五章：输入输出管理

| 考点 | 要点 |
|------|------|
| I/O 控制发展 | 程序直接控制 → 中断 → DMA → 通道 |
| DMA 传输单位 | **块** |
| 通道传输单位 | **一组块** |
| 单缓冲公式 | max(C,T) + M |
| 双缓冲公式 | max(C+M, T) |
| SPOOLing | 将独占设备改造为共享设备 |

## 三、计算题核心套路

### 套路一：银行家算法

1. 计算 `Need = Max - Allocation`
2. 检查 `Request ≤ Need` 且 `Request ≤ Available`
3. 试分配：`Available -= Request; Allocation += Request; Need -= Request`
4. 安全性检查：循环查找 `Need[i] ≤ Work` 的进程
5. 全部完成 → 安全（给出安全序列）；否则 → 不安全（拒绝分配）

### 套路二：页面置换算法

1. 确认物理块数和页面引用串
2. 按算法规则逐页处理：
   - OPT：替换未来最远使用的页
   - FIFO：替换最早进入内存的页
   - LRU：替换最近最久未使用的页
   - CLOCK：循环找使用位=0 的页
3. 统计缺页次数和缺页率

### 套路三：磁盘调度算法

1. 确认当前磁头位置和**移动方向**
2. 按算法规则排列请求序列
3. 计算磁头总移动磁道数
4. 平均寻道长度 = 总移动磁道数 / 请求数

### 套路四：缓冲区时间计算

| 场景 | 公式 |
|------|------|
| 单缓冲 | max(C, T) + M |
| 双缓冲 | max(C + M, T) |
| n 块数据总时间 | 用公式算单块时间 × (n-1) + 首/尾特殊处理 |

## 四、易错辨析

| 易错点 | 正确理解 |
|--------|---------|
| "进程调度一定发生进程切换" | ❌ 若选中的还是当前进程则不切换 |
| "系统调用是特权指令" | ❌ 系统调用运行在核心态，但**访管指令不是特权指令** |
| "阻塞态可以直接变运行态" | ❌ 必须先变就绪态 |
| "页面越多TLB命中率越高" | ❌ TLB 容量有限，命中率取决于局部性 |
| "虚拟内存容量=内存+外存" | ❌ 虚拟内存实际容量 ≤ 内存+外存；最大容量由地址位数决定 |
| "不安全状态=死锁" | ❌ 不安全状态不一定死锁 |
| "同一进程的线程切换会导致进程切换" | ❌ 同一进程内线程切换不会引起进程切换 |
| "管道通信是全双工" | ❌ 管道是**半双工**，全双工需要两个管道 |
| "CLOCK=LRU" | ❌ CLOCK 性能**接近** LRU，但不等于 LRU |
| "连续分配有内部碎片" | ❌ 连续分配（动态分区）产生的是**外部碎片** |

## 六、PV 操作大题解题通用模板

### 6.1 PV 操作四步通用方法

**第 1 步：分析问题，找出进程和临界资源**
- 明确有哪些进程
- 明确有哪些临界资源（互斥资源）
- 明确进程之间的同步关系

**第 2 步：设置信号量**
- 互斥信号量：初值为 1，用于保护临界资源
- 同步信号量：初值根据资源数量或同步条件确定
- 命名规范：mutex（互斥）、empty（空闲）、full（满）等

**第 3 步：写出 PV 操作**
- **P 操作在前，V 操作在后**
- **同步 P 在互斥 P 之前**（防止死锁）
- **互斥 V 在同步 V 之前**
- 成对出现，不能遗漏

**第 4 步：检查正确性**
- 检查是否满足互斥要求
- 检查是否满足同步要求
- 检查是否会发生死锁

### 6.2 经典问题模板

#### 生产者-消费者问题

```c
semaphore mutex = 1;      // 互斥访问缓冲区
semaphore empty = n;      // 空闲缓冲区数量
semaphore full = 0;       // 满缓冲区数量

producer() {
    while(1) {
        生产一个产品;
        P(empty);         // 申请空闲缓冲区
        P(mutex);         // 进入临界区
        将产品放入缓冲区;
        V(mutex);         // 离开临界区
        V(full);          // 增加满缓冲区数量
    }
}

consumer() {
    while(1) {
        P(full);          // 申请满缓冲区
        P(mutex);         // 进入临界区
        从缓冲区取出产品;
        V(mutex);         // 离开临界区
        V(empty);         // 增加空闲缓冲区数量
        消费产品;
    }
}
```

> [!IMPORTANT] 关键点
> 1. 同步 P 操作（empty/full）必须在互斥 P 操作（mutex）之前
> 2. 互斥 V 操作（mutex）必须在同步 V 操作（empty/full）之前
> 3. 这样可以避免死锁

#### 读者-写者问题（读优先）

```c
semaphore mutex = 1;      // 保护 count
semaphore rw = 1;         // 读写互斥
int count = 0;            // 读者数量

reader() {
    while(1) {
        P(mutex);
        count++;
        if(count == 1)    // 第一个读者
            P(rw);        // 阻止写者
        V(mutex);
        
        读数据;
        
        P(mutex);
        count--;
        if(count == 0)    // 最后一个读者
            V(rw);        // 允许写者
        V(mutex);
    }
}

writer() {
    while(1) {
        P(rw);
        写数据;
        V(rw);
    }
}
```

#### 读者-写者问题（写优先）

```c
semaphore rmutex = 1;     // 保护 rcount
semaphore wmutex = 1;     // 保护 wcount
semaphore r = 1;          // 读者排队
semaphore w = 1;          // 写者排队
int rcount = 0;           // 读者数量
int wcount = 0;           // 写者数量

reader() {
    while(1) {
        P(r);             // 读者排队
        P(rmutex);
        rcount++;
        if(rcount == 1)
            P(w);         // 第一个读者阻止写者
        V(rmutex);
        V(r);
        
        读数据;
        
        P(rmutex);
        rcount--;
        if(rcount == 0)
            V(w);         // 最后一个读者允许写者
        V(rmutex);
    }
}

writer() {
    while(1) {
        P(wmutex);
        wcount++;
        if(wcount == 1)
            P(r);         // 第一个写者阻止读者
        V(wmutex);
        
        P(w);
        写数据;
        V(w);
        
        P(wmutex);
        wcount--;
        if(wcount == 0)
            V(r);         // 最后一个写者允许读者
        V(wmutex);
    }
}
```

```c
philosopher(int i) {

        count++;

            V(mutex);
        }
```


### 6.3 PV 操作常见错误

| 错误类型 | 表现 | 后果 |
|---------|------|------|
| P、V 操作不配对 | 只有 P 没有 V | 资源永久被占用 |
| P、V 操作顺序错误 | 互斥 P 在同步 P 之前 | 可能死锁 |
| 信号量初值错误 | 互斥信号量初值不为 1 | 无法正确互斥 |
| 临界区范围过大 | 不必要的代码在临界区内 | 降低并发度 |
| 临界区范围过小 | 应保护的代码未保护 | 出现竞态条件 |

## 七、银行家算法计算步骤

### 7.1 算法核心思想

在分配资源前，先判断分配后系统是否处于安全状态，若安全则分配，否则拒绝。

### 7.2 数据结构

- **Available**：可用资源向量，长度为 m（m 种资源）
- **Max**：最大需求矩阵，n×m（n 个进程）
- **Allocation**：已分配矩阵，n×m
- **Need**：还需要矩阵，n×m，Need = Max - Allocation
- **Request**：请求向量，长度为 m

### 7.3 计算步骤

**第 1 步：检查请求合法性**
- 若 Request ≤ Need，转第 2 步
- 否则，出错（请求超过声明的最大需求）

**第 2 步：检查资源是否充足**
- 若 Request ≤ Available，转第 3 步
- 否则，进程等待

**第 3 步：试分配**
```
Available = Available - Request
Allocation = Allocation + Request
Need = Need - Request
```

**第 4 步：安全性检查**

初始化：
- Work = Available（工作向量）
- Finish[i] = false（完成标记）

循环查找满足条件的进程：
1. 找到 Finish[i] = false 且 Need[i] ≤ Work 的进程 i
2. 若找到，则：
   - Work = Work + Allocation[i]
   - Finish[i] = true
   - 记录进程 i 到安全序列
3. 重复步骤 1-2，直到所有进程都完成或找不到满足条件的进程

**第 5 步：判断结果**
- 若所有 Finish[i] = true，则系统安全，分配成功
- 否则，系统不安全，恢复试分配前的状态，进程等待

### 7.4 例题模板

**【例】** 某系统有 3 种资源 A、B、C，数量分别为 10、5、7。在 T0 时刻的资源分配情况如下：

| 进程 | Max(A,B,C) | Allocation(A,B,C) | Need(A,B,C) |
|------|-----------|------------------|------------|
| P0 | 7,5,3 | 0,1,0 | 7,4,3 |
| P1 | 3,2,2 | 2,0,0 | 1,2,2 |
| P2 | 9,0,2 | 3,0,2 | 6,0,0 |
| P3 | 2,2,2 | 2,1,1 | 0,1,1 |
| P4 | 4,3,3 | 0,0,2 | 4,3,1 |

Available = (3,3,2)

问：若 P1 请求资源 (1,0,2)，能否分配？

**解答**：

1. Request(1,0,2) ≤ Need(1,2,2)，合法
2. Request(1,0,2) ≤ Available(3,3,2)，资源充足
3. 试分配：
   - Available = (3,3,2) - (1,0,2) = (2,3,0)
   - Allocation[P1] = (2,0,0) + (1,0,2) = (3,0,2)
   - Need[P1] = (1,2,2) - (1,0,2) = (0,2,0)
4. 安全性检查：
   - Work = (2,3,0)
   - 找 P1：Need(0,2,0) ≤ Work(2,3,0)，Work = (2,3,0) + (3,0,2) = (5,3,2)
   - 找 P3：Need(0,1,1) ≤ Work(5,3,2)，Work = (5,3,2) + (2,1,1) = (7,4,3)
   - 找 P4：Need(4,3,1) ≤ Work(7,4,3)，Work = (7,4,3) + (0,0,2) = (7,4,5)
   - 找 P0：Need(7,4,3) ≤ Work(7,4,5)，Work = (7,4,5) + (0,1,0) = (7,5,5)
   - 找 P2：Need(6,0,0) ≤ Work(7,5,5)，Work = (7,5,5) + (3,0,2) = (10,5,7)
   - 安全序列：P1 → P3 → P4 → P0 → P2
5. 系统安全，可以分配
