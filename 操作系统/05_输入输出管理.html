05 输入输出管理 ​

本章涵盖 I/O 设备管理的核心内容：I/O 控制方式、软件层次结构、缓冲区管理、设备分配与回收以及 SPOOLing 假脱机技术。以选择题为主。

一、I/O 设备概述 ​

1.1 设备分类 ​

按使用类型：人机交互类（字节交换）、存储设备（块交换）、网络通信设备

按传输速率：低速设备（键鼠）→ 中速设备（打印机）→ 高速设备（磁盘）

按信息交换单位：

类型特点示例
块设备传输率高、可寻址、随机读写磁盘
字符设备传输率低、不可寻址、中断驱动键盘

二、I/O 控制方式 ​

方式原理CPU 介入程度数据传输单位
程序直接控制CPU 轮询检查 I/O 状态极高（忙等）字
中断驱动I/O 完成后通过中断通知 CPU较高（每字中断一次）字
DMAI/O 与内存直接传输低（仅传送开始和结束时介入）块
通道控制专用 I/O 处理机执行通道程序最低一组块

DMA 方式详解 ​

DMA 控制器包含 4 个寄存器：

  • CR（命令/状态寄存器）：接收 CPU 的 I/O 命令
  • MAR（内存地址寄存器）：数据在内存中的位置
  • DR（数据寄存器）：暂存传输数据
  • DC（数据计数器）：本次传送的字节数

DMA 与中断驱动的区别：

  1. 中断驱动每字都要中断 CPU；DMA 传送完一批数据后才中断
  2. 中断驱动时CPU 传输数据；DMA 由 DMA 控制器传输

通道控制方式 ​

  • I/O 通道是专门负责输入/输出的处理机
  • 指令类型单一，没有自己的内存，通道程序放在主存中
  • 一个通道可以控制多台设备（DMA 控制器只对应一台设备）

三、I/O 软件层次结构 ​

从上到下依次为：

用户层 I/O 软件（库函数）
        ↓ 系统调用

        ↓
中断处理程序（最底层）

设备独立性软件 ​

实现设备独立性（设备无关性）：应用程序独立于具体物理设备，使用逻辑设备名请求。

主要功能：设备分配与回收、逻辑设备名 → 物理设备名映射、设备保护、缓冲管理、差错控制、提供统一接口。

设备驱动程序 ​

  • 每类设备配置一个设备驱动程序
  • 与硬件直接相关，把上层命令转换为具体设备操作
  • 向上提供标准接口，封装设备差异

四、缓冲区管理 ​

引入缓冲区的目的：

  1. 缓和 CPU 与 I/O 设备间速度不匹配
  2. 减少 CPU 中断频率
  3. 解决数据单元大小不匹配
  4. 提高 CPU 和 I/O 设备的并行性

4.1 单缓冲 ​

设 T=设备输入时间，M=缓冲区→用户区传送时间，C=CPU 处理时间：

处理一块数据用时=max(C,T)+M

单缓冲时间公式

CPU 的传送（M）和处理（C）不能并行，但都可以和设备输入（T）并行。初始状态：工作区满，缓冲区空。

4.2 双缓冲 ​

处理一块数据用时=max(C+M,T)
  • 若 T>C+M：设备连续输入
  • 若 T<C+M：CPU 不必等待设备
  • 双缓冲可实现双向数据传输（单缓冲只能单向）

4.3 循环缓冲 ​

多个大小相等的缓冲区以循环链表方式链接，使用 in 和 out 指针管理。

4.4 缓冲池 ​

多个系统公用的缓冲区组成，包含三个队列：

  • 空缓冲队列
  • 输入队列（装满输入数据）
  • 输出队列（装满输出数据）

4 种工作缓冲区：收容输入 → 提取输入 → 收容输出 → 提取输出。

4.5 高速缓存 vs 缓冲区 ​

高速缓存 (Cache)缓冲区 (Buffer)
存放内容低速设备数据的副本低速设备数据的本体
目的加速访问速度协调速度差异
命中时不需要访问低速设备仍需等待数据传入/传出

4.6 I/O 大题计算详解 ​

单缓冲推导过程 ​

假设初始状态：工作区满，缓冲区空

情况 1：若 T>C

  • 工作区处理数据（用时 C），同时缓冲区接收数据
  • C 时刻：工作区处理完，但缓冲区还未满
  • T 时刻：缓冲区接收完毕
  • 传送数据到工作区（用时 M）
  • 总用时 = T+M

情况 2：若 T<C

  • 缓冲区接收数据（用时 T），同时工作区处理数据
  • T 时刻：缓冲区接收完，但工作区还未处理完
  • C 时刻：工作区处理完毕
  • 传送数据到工作区（用时 M）
  • 总用时 = C+M

综合：max(C,T)+M

双缓冲推导过程 ​

假设初始状态：工作区空，缓冲区 1 满，缓冲区 2 空

情况 1：若 T>C+M

  • 缓冲区 1 → 工作区（用时 M），同时缓冲区 2 接收数据
  • 工作区处理数据（用时 C），缓冲区 2 继续接收
  • C+M 时刻：工作区处理完，缓冲区 2 还未满
  • T 时刻：缓冲区 2 接收完毕，回到初始状态
  • 总用时 = T

情况 2：若 T<C+M

  • 缓冲区 1 → 工作区（用时 M），同时缓冲区 2 接收数据
  • T 时刻：缓冲区 2 接收完毕
  • 工作区继续处理数据
  • C+M 时刻：工作区处理完毕，回到初始状态
  • 总用时 = C+M

综合：max(C+M,T)

计算套路总结 ​

通用步骤：

  1. 明确参数：

    • T：设备输入一块数据到缓冲区的时间
    • M：缓冲区数据传送到用户区的时间
    • C：CPU 处理一块数据的时间

  2. 画时序图：

    • 标出各阶段的起止时间
    • 注意哪些操作可以并行

  3. 找初始状态：

    • 单缓冲：工作区满，缓冲区空
    • 双缓冲：工作区空，一个缓冲区满，另一个空

  4. 计算到下一个相同状态的时间

常见变式：

题型公式
单缓冲处理 n 块数据(n−1)×max(C,T)+T+M+C
双缓冲处理 n 块数据(n−1)×max(C+M,T)+T+M+C
循环缓冲（k 个缓冲区）需具体分析，通常能进一步提高并行度

易错点

  1. 注意 M 和 C 是否能并行（单缓冲不能，双缓冲也不能）
  2. 注意 T 和 C 是否能并行（都能）
  3. 注意 T 和 M 是否能并行（双缓冲能，单缓冲不能）

【例题】：某系统采用单缓冲策略，设备输入一块数据到缓冲区需要 T=10ms，CPU 将缓冲区数据传送到用户区需要 M=2ms，CPU 处理一块数据需要 C=8ms。求：

  1. 处理一块数据需要多长时间？
  2. 连续处理 100 块数据需要多长时间？

解答：

  1. 处理一块数据：max(C,T)+M=max(8,10)+2=12ms
  2. 连续处理 100 块：(100−1)×12+10+2+8=1208ms

五、设备分配与回收 ​

5.1 分配方式 ​

方式特点
独占式申请时若空闲则独占，直到释放
分时式共享多进程分时使用
SPOOLing将独占设备改造为共享设备

5.2 数据结构 ​

分配过程涉及 4 张表：

系统设备表 (SDT) → 设备控制表 (DCT) → 控制器控制表 (COCT) → 通道控制表 (CHCT)
1

一个通道 → 多个控制器 → 每个控制器多个设备

5.3 分配步骤 ​

  1. 根据逻辑设备名查 SDT → 找到空闲设备 → 分配设备
  2. 根据 DCT 找到 COCT → 分配控制器
  3. 根据 COCT 找到 CHCT → 分配通道
  4. 三者都可用时分配成功

5.4 分配安全性 ​

方式特点
安全分配I/O 请求后进入阻塞态，不会死锁，但串行
不安全分配I/O 请求后继续运行，效率高但可能死锁

5.5 逻辑设备表 (LUT) ​

实现逻辑设备名 → 物理设备名的映射。

表项：逻辑设备名、物理设备名、设备驱动程序入口地址。

组成部分：

  • 输入井/输出井：磁盘上的存储区域
  • 输入/输出缓冲区：内存中的缓冲区
  • 输入/输出进程：模拟脱机时的外围控制机

SPOOLing 的主要特点：

  1. 提高了 I/O 速度（用户只与磁盘交互）
  2. 将独占设备改造为共享设备
  3. 实现了虚拟设备功能

共享打印机

SPOOLing 最经典的应用。用户请求打印时：①在输出井中申请空闲磁盘区存放数据；②申请空白打印请求表，挂到请求打印队列。

七、I/O 大题：CPU 占用率计算 ​

高频大题模板

I/O 方式的 CPU 占用率计算在计组和 OS 中均可考查，核心思路固定。

7.1 通用计算公式 ​

CPU 占用率=每秒中断次数×每次中断的时钟周期数主频（每秒总时钟周期数）

7.2 中断驱动方式 ​

  • 每传送 1 个字/字节就中断一次
  • 每秒中断次数 = I/O 数据传输率 ÷ 每次传送的数据量
  • 每次中断开销 = 中断响应 + 中断处理（设备服务）的时钟周期数

【例】 磁盘以 1MB/s 速率传输数据，每次传送 32 位（4B），中断处理需 100 个时钟周期，CPU 主频 1GHz。

  • 每秒中断次数 = 106/4=250000 次
  • CPU 占用率 = 250000×100/109=2.5%

7.3 DMA 方式 ​

  • 每传送完一个数据块才中断一次
  • 每秒中断次数 = I/O 数据传输率 ÷ 数据块大小
  • 通常远少于中断驱动

【例】 同上磁盘，DMA 每次传送 4KB，中断处理 500 周期。

  • 每秒中断次数 = 106/4096≈244 次
  • CPU 占用率 = 244×500/109≈0.012%

7.4 数据丢失判断 ​

数据丢失条件

若准备数据的时间 < 取走数据的时间，缓冲区数据会被覆盖导致丢失。

最大准备时间=缓冲区大小I/O 速率

每轮查询/中断的处理时间必须 ≤ 最大准备时间，否则数据丢失。
